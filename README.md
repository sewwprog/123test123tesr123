# AHLTV Ryota Tournaments

Статичний сайт турнірів 1×1 і 2×2: заявки, акаунти, турнірна сітка, рейтинг та панель організатора. Бойова версія використовує Firebase Authentication і Cloud Firestore; структура наявних колекцій збережена.

## Запуск

Збірка не потрібна. Із кореня репозиторію запустіть, наприклад:

```sh
python3 -m http.server 8000
```

Відкрийте `http://localhost:8000/`. Для Firebase потрібні інтернет, увімкнений вхід через email/password і дозволений домен у **Authentication → Settings → Authorized domains**. На GitHub Pages файли працюють зі звичайної підпапки репозиторію; навігація використовує `#`-адреси.

### Демо без Firebase

Відкрийте `http://localhost:8000/?demo=1`. Демо використовує старі ключі `ah_*` у `localStorage` цього браузера і **не надсилає заявки на справжній турнір**. Не використовуйте справжні паролі в демо. Якщо Firebase не завантажився, сайт показує помилку й пропонує демо окремо, замість непомітного переходу в локальну базу.

## Що важливо для організатора

- У сітці заявки на перевірці показано напівпрозорими: рахунок можна внести лише для підтверджених учасників. Їхні місця збережено для сумісності з попередніми результатами. Ліміт — 16 підтверджених учасників/пар на режим.
- До фіналу рахунок вводиться за картами до 2 перемог, у фіналі — до 3. За відсутності суперника адмін може вручну підтвердити прохід без гри. Він недоступний, якщо суперник ще може з'явитися з незавершеного попереднього матчу.
- Зміна результату очищає залежні результати наступних раундів. Перестановка, відхилення, підтвердження, видалення або зміна режиму учасника сітки очищає результати відповідних сіток після попередження. На телефоні місця можна міняти через вибір учасника і позиції. Наявну розкладку можна окремо закріпити без скидання результатів; при записі рахунку поточні місця закріплюються автоматично.
- Новий час старту зберігається в UTC, а відвідувачі бачать його у своєму часовому поясі. Старі значення без часового поясу інтерпретуються за локальним часом пристрою; за потреби повторно збережіть дату в адмінці.
- Старі заявки, профілі, звичайні рядкові рахунки та списки адмінів читаються у попередньому форматі. Порожній список адмінів у `cfg/main` має пріоритет над старим `cfg/admins`, щоб видалені адміни не поверталися через застарілу копію.

## Firebase та безпека

Публічний конфіг вебклієнта й email власника розміщено в `assets/app.js`. Firebase API key для вебклієнта не замінює правила доступу. **Прихована кнопка адмінки та перевірки в браузері не захищають базу.**

Перед публікацією власник має перевірити чинні Firestore Rules у Firebase Console: лише власник/уповноважені адміни повинні змінювати налаштування, результати й заявки інших користувачів; користувачі — читати й змінювати лише свої приватні заявки та профілі; публічні `slots` не повинні містити пошту. Права адміна слід надавати лише підтвердженим акаунтам. Правила та конфігурація існуючого Firebase-проєкту **цим репозиторієм автоматично не змінюються**.

Для сумісності зі старою версією список адмінів може зберігатися у `cfg/main.admins`, а `cfg/main` використовується для публічної дати старту. Якщо документ доступний усім, ці адреси також доступні всім: перевірте поточні правила та, за потреби, перенесіть ролі до захищеної серверної схеми. Обмеження кількості та повторних заявок у браузері не замінюють атомарні перевірки на сервері, особливо при одночасних діях з різних пристроїв.

## Тести

Для браузерних тестів потрібен Node.js 20+ та Chromium Playwright:

```sh
npm ci
npx playwright install chromium
npm run check
npm test
```

Тести перевіряють навігацію, мобільне меню, реєстрацію, акаунт, адмінку, сітку, рахунки й обробку помилок. Firebase у них замінено тестовим двійником: це **не** перевірка правил або підключення до бойового Firebase.

## Файли

- `index.html` — розмітка сторінок;
- `assets/styles.css` — адаптивні стилі;
- `assets/app.js` — навігація, логіка турніру та адаптери Firebase/демо;
- `assets/arena-hero.jpg` — оформлення головного екрана;
- `tests/` — браузерні тести та тестові Firebase-модулі.
